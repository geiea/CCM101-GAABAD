# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

For me, the **compute resource** is the most important cloud infrastructure component because it is responsible for processing tasks and running applications. Without enough CPU and memory, other resources would not be able to support applications properly. It is also important because cloud services depend on computing power to perform different operations.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a stable environment where applications and cloud services can run. It also allows users to manage resources through the terminal and use different commands to monitor the system. In this activity, KillerCoda helped me practice using Linux commands to check the server's CPU, memory, storage, and network information.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it helps organize information about the infrastructure before it is deployed. It allows engineers to understand the resources, configurations, and design of a system. Good documentation can also make troubleshooting and future maintenance easier.

## 4. What new skills did you learn during this laboratory activity?

I learned how to investigate a Linux server using different commands. I became more familiar with checking CPU, RAM, storage, networking, and system information. I also learned how to compare similar services from AWS, Microsoft Azure, and Google Cloud Platform and how to organize technical information using Markdown.

## 5. How has your GitHub portfolio improved after completing this mission?

My GitHub portfolio became more organized and informative after completing this mission. I added different Markdown files containing my infrastructure findings, cloud component explanations, provider comparison, and reflection. This also gave me experience in documenting my work and maintaining a more complete cloud computing portfolio.
